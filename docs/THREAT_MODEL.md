# Shipkeep Threat Model

Living document. Update it in the same PR as any change to the agent, authentication, secrets, builds or the action catalogue.

## Assets

1. User servers (root-equivalent access through Docker).
2. Application secrets and database credentials.
3. User data in volumes, databases and backups.
4. Control plane database, internal CA private key, KEK.
5. Source code access tokens (GitHub App private key, GitLab tokens).
6. Integrity of deployed images and of Shipkeep's own release artifacts.

## Trust boundaries

```text
Internet users ──HTTPS──> Caddy on nodes ──> app containers
Team members ──HTTPS──> Control plane API/UI
Git providers ──webhooks──> Control plane API
Agents ──mTLS gRPC (outbound)──> Control plane agent gateway
Nodes <──WireGuard──> Nodes
Build containers (untrusted code) inside rootless BuildKit
```

## Lessons from Coolify's 2025-2026 CVEs

| Coolify flaw class                               | Example                                                    | Shipkeep mitigation                                                                                                                     |
| ------------------------------------------------ | ---------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Command injection from UI fields into host shell | Git source fields, `network` parameter, image name handler | No shell anywhere; typed actions; agent-side validation; CI rule blocking `exec.Command` with non-literal args and Node `child_process` |
| Docker Compose injection to RCE                  | Compose content executed with host privileges              | Compose parsed and validated by the control plane; dangerous keys rejected (SPEC 2.2); containers created through typed `ContainerSpec` |
| Build context escape to host                     | Helper image build executing host commands                 | Rootless BuildKit; no Docker socket in builds; resource limits                                                                          |
| Secret material leaked to low-privileged users   | Root SSH private key readable by members                   | No SSH keys stored; secrets write-only through the API; RBAC tested per endpoint                                                        |
| Missing authorization checks                     | Policy handler without authorization                       | Default-deny guard on every controller; RBAC matrix tests generated for every route                                                     |
| Token injection into host config                 | Sentinel token injection                                   | Tokens are opaque random values, never interpolated into commands or files                                                              |
| Destructive defaults                             | Unused volumes deleted by default                          | Confirmation tokens for destructive actions; no destructive default                                                                     |

## Security engineering requirements

- Tenant SQL tables force row-level policies on transaction-local organization context. Restricted-role PostgreSQL tests cover missing context, foreign reads/writes, table-owner queries, attempted RLS disabling and context cleanup. Membership changes take a write lock on the organization; deferred ownership checks reject simultaneous removal of the last owners under both read-committed and repeatable-read isolation. Runtime database-role enforcement and HTTP tenant resolution must be installed before exposing organization endpoints.

- SMTP delivery requires verified implicit TLS. Loopback TLS-server tests prove that untrusted and wrong-host certificates fail before authentication, valid delivery succeeds, and recipient header injection is rejected. Unit tests enforce a hard delivery deadline and opaque transport errors. Email credentials never appear in navigation URLs; the public control-plane origin requires HTTPS in production.

- Identity email jobs are encrypted and transactionally coupled to their credential and audit. Real PostgreSQL/pg-boss tests prove rollback, delivery after restart, retry without transport-error disclosure, rejection of tampered ciphertext and suppression of expired credentials. The queue's schema and names are fixed; its upstream Prisma adapter binds values as parameters. SMTP is isolated behind a delivery port and never runs in the command transaction.

- Authentication attempt reservations are atomic PostgreSQL upserts shared by all API instances. Tests prove concurrent requests cannot bypass account delays, account cycling cannot bypass IP quotas, successful login does not reset the IP quota, rejected retries cannot extend lockouts, failures from one network cannot lock the owner out from another, and addresses of one IPv6 /64 share a quota. Stored limiter keys contain purpose-bound hashes rather than raw email/IP values; bounded expiry cleanup removes old buckets.

- Identity mutations lock the user row before security-sensitive changes. Password changes increment the security version and invalidate sessions and reset tokens in the same transaction as their audit. Credential claims are conditional updates; session activity only advances and cannot revive an expired, revoked, disabled-owner or stale-version session. Real PostgreSQL tests cover concurrent mutations and rollback after credential consumption.

- Identity primitives bound password length, Argon2id memory/concurrency and TOTP windows. Tests cover missing accounts, invalid stored hashes, Unicode passphrases, exact session expiry boundaries, RFC 6238 vectors and replayed TOTP counters. Bearer secrets use purpose-separated hashes and redacting wrappers. Persistence must atomically claim counters and recovery codes before authorizing a request.
- HTTP session guards deny access unless a route explicitly allows anonymous requests. Browser mutations require the exact configured origin; authenticated mutations additionally require a session-bound CSRF header. HTTPS cookies use the `__Host-` prefix, Secure, SameSite=Strict and HttpOnly for the session. Tests reject duplicate cookies, cross-site requests, spoofed forwarding headers and bearer-to-cookie fallback; persistent throttling exposes bounded retry metadata. Controller registration is tracked separately in M2.2c4b.
- Request logs and problem instances retain only URL paths, removing query strings and fragments. Framework HTTP errors return fixed status text because parser and router messages can echo credentials. Unexpected exceptions are logged with request ID, path and status only, never raw driver/parser errors. Tests exercise malformed credential JSON, query tokens and sensitive exception messages across responses and error logs. Domain validation keeps its explicit, reviewed public messages.

- Operation execution records intent before effects, binds idempotency to a versioned plan and serializes execution within the process lock. Crash injection after every step proves retry-safe resume and reverse compensation for uncertain non-idempotent work; compensation crashes, concurrent replays and shutdown cancellation retain recoverable checkpoints. Raw callback error text is not persisted.

- Cached protobuf state is copied and recursively stripped of secret-marked and unknown fields before persistence. Tests inspect both SQLite and its sidecars for secret fixtures, reject stale/conflicting snapshots and prove single-use confirmation consumption under concurrency and after restart.

- The agent journal stores hashes instead of action payloads and bounded outcome metadata instead of raw output/errors. Private SQLite files, an exclusive process lock, durable transactions and revision checks prevent concurrent execution or checkpoint replacement. Tests cover conflicting replays, duplicate submissions and restart persistence.

- A wrong CA fingerprint, rogue CA, hostname mismatch or expired server certificate prevents any enrollment RPC and join-token disclosure. Bootstrap uses a custom verifier only for a payload-free TLS probe; all application traffic uses standard TLS verification against the verified root. Tests exercise real Go TLS/gRPC servers and token-echoing error responses.

- Agent credential loading rejects symlinks, oversized files, loose permissions, key/certificate mismatches and tenant/node identity substitutions. Keys use the redacting Go `Secret` wrapper; only the explicit atomic persistence boundary writes private material.

- Gateway enrollment shares the TLS listener with protected RPCs: TLS requests (but does not require) a client certificate so a fresh agent can enroll. Application-level authentication is default-deny for every RPC except `Enroll`, derives identity only from the verified TLS peer, and checks the serial against the database on every call. TLS and PostgreSQL integration tests cover missing and unregistered certificates, revoked serials on reused connections, spoofed identity headers, CA trust and hostname verification. The Connect stream validates the initial node/epoch Hello, bounds idle time to 15 seconds, permits only one active stream per node and checks current credentials at least every second even for silent peers. Database failures close streams without exposing error details; integration tests cover forged identities, stale epochs, duplicate connections and live revocation. ExecStream remains unavailable pending session authorization.

- Static analysis in CI: Semgrep (custom rules below), gosec, golangci-lint, gitleaks, Trivy filesystem scan. CodeQL (TypeScript, Go) once the repository is public. Trivy image scan of the control plane image is added to the release workflow in task M8.3.
- All third-party GitHub Actions pinned to full commit SHAs and all tool images to digests (the March 2026 trivy-action compromise, CVE-2026-33634, rewrote version tags).
- Custom Semgrep rules in `.semgrep/rules/shipkeep-rules.yml`, failing CI, each proven by `.semgrep/tests/` (`pnpm semgrep:test`):
  - Go: `exec.Command` or `exec.CommandContext` with a non-literal program; any shell interpreter as program (`sh`, `bash`, `dash`, `zsh`, `busybox`, `cmd`, `powershell`, under any path); a `-c` argument; raw spawning through `syscall.Exec`, `syscall.ForkExec`, `os.StartProcess`.
  - Go: Docker `HostConfig` with `Privileged`, or `host` PID, IPC, network or user namespaces.
  - TypeScript: any static or dynamic import of `child_process`, `execa`, `shelljs`, `zx`, `cross-spawn`, `node-pty`.
  - TypeScript: Prisma `$queryRawUnsafe` and `$executeRawUnsafe`.
  - TypeScript: `eval`, `new Function`, string arguments to `setTimeout` and `setInterval`.
- Fuzzing (Go native fuzzing) for: `shipkeep.yml` parser (Go side), Compose validator, every agent action validator, routing table builder.
- Dependency updates through Renovate, security updates merged within 7 days.
- Release artifacts: signed with cosign keyless, SBOM (SPDX) generated with Syft, provenance attestation.
- `SECURITY.md` with a disclosure process and a 90-day disclosure policy from v0.1; a dedicated security email address is added once the project domain is registered.
- External security audit before v1.0.
